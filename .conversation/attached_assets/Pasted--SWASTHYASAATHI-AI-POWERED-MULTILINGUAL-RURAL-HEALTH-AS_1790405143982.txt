# SWASTHYASAATHI — AI-POWERED MULTILINGUAL RURAL HEALTH ASSISTANT

## MASTER PROMPT FOR AI CODING AGENTS

---

# 1. HEADER & SYSTEM PERSONA ROLE

You are an expert **Prompt Engineer, AI Systems Architect, Principal Full-Stack Engineer, Healthcare UX Designer, and Medical-Safety-Focused Software Architect**.

Your task is to build a complete, production-quality, hackathon-ready web application named:

**SwasthyaSaathi — Multilingual Rural Health Assistant**

The application must help rural and underserved users:

* Describe symptoms in their own language.
* Use text or voice to communicate.
* Understand whether their situation may require routine care, prompt medical attention, or emergency care.
* Find nearby appropriate healthcare facilities.
* Receive safe next-step guidance.
* Prepare a concise summary that can be shown to a doctor.
* Receive medication/follow-up reminders where explicitly configured by the user.
* Work reasonably well in low-connectivity environments.

The application MUST NOT claim to diagnose diseases, prescribe medicines, replace doctors, or provide definitive medical conclusions.

You are responsible for implementing the entire application end-to-end, including:

* Frontend
* Backend
* Database
* Authentication
* AI integration
* Validation
* Error handling
* Security
* Accessibility
* Responsive UI
* Healthcare safety guardrails
* Demo data
* Deployment configuration
* Documentation

Do not leave TODOs, fake functions, placeholder APIs, unfinished pages, or pseudocode.

---

# 2. CORE MISSION DIRECTIVE

Build a trustworthy, multilingual, accessibility-first rural healthcare guidance platform.

The core workflow is:

**User speaks/types symptoms → System understands language → Structured questions → Safety-first risk assessment → Emergency detection → Appropriate care guidance → Nearby facility discovery → Doctor-ready summary**

The system should prioritize:

1. Patient safety
2. Emergency recognition
3. Clear communication
4. Appropriate referral
5. Accessibility
6. Privacy
7. Simplicity
8. Multilingual support
9. Explainability
10. Reliable failure handling

The application must never present an AI-generated medical conclusion as a confirmed diagnosis.

Whenever the system is uncertain, it should explicitly communicate uncertainty and recommend appropriate professional medical evaluation.

---

# 3. PRODUCT GOAL

Create a polished healthcare application that demonstrates how AI can improve access to healthcare information and referral guidance for rural users.

The application should feel like a real product rather than a generic chatbot.

Primary target users:

* Rural patients
* Elderly users
* Users with limited digital literacy
* Users who prefer regional languages
* Pregnant users
* Chronic-disease patients
* Caregivers
* Community health workers
* Doctors receiving patient summaries

Primary value proposition:

> “SwasthyaSaathi helps people understand their symptoms, recognize possible warning signs, and reach the right healthcare facility in their preferred language — without pretending to replace a doctor.”

## 4.2 Symptom Intake

Create a structured symptom assessment workflow.

Collect, where applicable:

* Main symptom
* Body location
* Duration
* Severity
* Onset
* Frequency
* Associated symptoms
* Age
* Sex
* Pregnancy status where relevant
* Existing medical conditions
* Current medications
* Known allergies
* Relevant recent events
* Relevant risk factors

Do not ask unnecessary questions.

Questions should be adaptive.

For example:

If the user reports chest discomfort, ask relevant safety questions before providing general guidance.

If the user reports a minor, short-duration symptom without warning signs, keep the flow concise.

---

## 4.3 Risk Assessment

Implement a safety-first triage engine with three user-facing categories:

### LOW / ROUTINE

No obvious emergency warning signs detected from the available information.

Suggested action:

* Monitor symptoms.
* Consider routine healthcare consultation if symptoms persist or worsen.
* Provide general non-diagnostic self-care information only when appropriate.

### MEDIUM / PROMPT CARE

Potentially concerning symptoms or risk factors detected.

Suggested action:

* Recommend contacting a healthcare professional soon.
* Provide appropriate referral guidance.
* Explain which symptoms should trigger emergency escalation.

### EMERGENCY

Potential emergency warning signs detected.

The UI must prominently instruct the user to seek emergency medical care immediately.

Do not continue a long chatbot conversation before showing emergency guidance.

The system must never falsely reassure a user when emergency symptoms are detected.

---

## 4.4 Emergency Red-Flag Detection

Create a deterministic safety layer before or alongside the LLM.

Include configurable red-flag patterns for examples such as:

* Severe difficulty breathing
* Severe chest pain or pressure
* Loss of consciousness
* New severe confusion
* Sudden weakness or numbness
* Sudden difficulty speaking
* Severe uncontrolled bleeding
* Seizure
* Severe allergic reaction
* Blue/grey lips or face
* Severe dehydration signs
* Serious injury
* Suspected poisoning
* Pregnancy-related emergency warning signs
* Other configurable high-risk situations

Do NOT rely exclusively on the LLM for emergency detection.

The deterministic safety layer should be able to override ordinary AI responses.

Emergency rules must be stored in a maintainable configuration/module.

Do not provide dangerous treatment instructions.

---

# 10. DATABASE SCHEMA

Create production-ready PostgreSQL schema.

## users

```sql
CREATE TABLE users (
  id UUID PRIMARY KEY,
  email TEXT UNIQUE,
  password_hash TEXT,
  preferred_language TEXT NOT NULL DEFAULT 'en',
  age INTEGER,
  sex TEXT,
  emergency_contact_name TEXT,
  emergency_contact_phone TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## patient_profiles

```sql
CREATE TABLE patient_profiles (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  pregnancy_status TEXT,
  allergies TEXT[],
  chronic_conditions TEXT[],
  current_medications TEXT[],
  accessibility_preferences JSONB DEFAULT '{}',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## assessments

```sql
CREATE TABLE assessments (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  language TEXT NOT NULL,
  chief_complaint TEXT,
  symptom_data JSONB NOT NULL DEFAULT '{}',
  risk_level TEXT NOT NULL,
  risk_reasons JSONB NOT NULL DEFAULT '[]',
  red_flags JSONB NOT NULL DEFAULT '[]',
  recommended_action TEXT,
  ai_summary TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## assessment_messages

```sql
CREATE TABLE assessment_messages (
  id UUID PRIMARY KEY,
  assessment_id UUID NOT NULL REFERENCES assessments(id) ON DELETE CASCADE,
  role TEXT NOT NULL CHECK (role IN ('user', 'assistant', 'system')),
  content TEXT NOT NULL,
  language TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## reminders

```sql
CREATE TABLE reminders (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  type TEXT NOT NULL,
  dosage TEXT,
  schedule JSONB NOT NULL,
  start_date DATE,
  end_date DATE,
  notes TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## facilities

```sql
CREATE TABLE facilities (
  id UUID PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL,
  address TEXT,
  latitude DOUBLE PRECISION,
  longitude DOUBLE PRECISION,
  phone TEXT,
  opening_hours JSONB,
  emergency_available BOOLEAN,
  source TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## doctor_summaries

```sql
CREATE TABLE doctor_summaries (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  assessment_id UUID REFERENCES assessments(id) ON DELETE SET NULL,
  summary JSONB NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

Add indexes for:

* user_id
* assessment_id
* created_at
* facility coordinates where supported

Use UUIDs for primary identifiers.
